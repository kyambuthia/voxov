# Releases

## Overview

VOXOV releases are automated with GitHub Actions when you push a semantic version tag.

Supported tag formats:

- `0.0.1`
- `v0.0.1`

The release workflow builds multi-platform artifacts and publishes them to GitHub Releases.

## What gets published

- `VOXOV-<tag>-linux-x86_64`
- `VOXOV-<tag>-windows-x86_64.zip`
- `VOXOV-<tag>-android-arm64-v8a.apk`

Naming format is intentional so users can identify platform/architecture quickly in release assets.

Notes:

- Linux asset is a direct executable.
- Windows asset is a zip containing `voxov.exe` (current CI release profile builds OpenGL-only on Windows for stability).
- Android asset is an installable APK (arm64-v8a).

## Release title and source archives

The workflow sets a human-readable release title:

- `VOXOV <tag> (Linux/Windows/Android)`

GitHub still shows default `Source code (zip)` and `Source code (tar.gz)` entries with archive icons.
Those are auto-generated by GitHub and are separate from your named binary assets.

## Create a release tag

From repository root:

```bash
git tag 0.0.1
git push origin 0.0.1
```

or with `v` prefix:

```bash
git tag v0.0.1
git push origin v0.0.1
```

## Workflow file

- `.github/workflows/release.yml`

## Notes

- The release build disables aggressive Jolt SIMD flags for broader CPU compatibility:
  - `USE_AVX2=OFF`
  - `USE_F16C=OFF`
  - `USE_FMADD=OFF`
  - `USE_LZCNT=OFF`
